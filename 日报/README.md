# 日报

本目录存放**主协调 Grok Bot**每天汇总的手下日报。

每天一份文件。内容是当天各专 bot 上报的**完整原文**，再加上主协调的**评判**（要点、分歧、遗漏、建议跟进）。不要只留摘要：专 bot 写了什么，这里就原样收进来，评判另起一节写清楚。

## 怎么看

用户日常只在这里看汇总日报。各专 bot 的原文对话仍在各自私聊里，本目录是汇总副本，不替代私聊。

打开当天文件即可，不需要再去翻各个 bot 的会话。

## 文件命名

```
YYYY-MM-DD.md
```

日期按 **Asia/Shanghai**（北京时间）计算，取当天自然日，不要用 UTC 日期。

示例：北京时间 2026-11-04 晚上写的汇总，文件名是 `2026-11-04.md`，即使此时 UTC 已经是 11 月 3 日或 5 日，也以北京时间为准。

一天一份。同一天若有补记，写进当天文件，不要另起新文件名。

## 单日文件建议结构

保持 Markdown 清爽，标题层级少，段落写完整。内容要详实，不要为了短而删掉专 bot 的具体说法。

建议按下面的顺序组织，专 bot 多的时候用二级标题分开：

1. **日期与范围** — 北京时间日期，覆盖的专 bot 名单，有没有缺报。
2. **各专 bot 日报（全文）** — 每个 bot 一节，原文完整保留，标明来源（bot 名称 / 会话）。
3. **主协调评判** — 当天判断：哪些一致、哪些冲突、哪些没人提、建议用户先看哪几条。
4. **待跟进** — 需要用户决定或明天继续盯的事项。没有就写「无」。

评判和原文分开，避免把主协调的话混进专 bot 原文里。

## 写作风格

- 用 Markdown：标题、列表、引用即可，不必堆表格或装饰。
- 详实优先。专 bot 的数字、链接、原话、不确定之处都留下来。
- 可以分段、加小标题，方便扫读，但不要把一段完整说明压成几个词。
- 不编造未收到的日报。某 bot 当天没交，在名单里标明缺报，不要补写假内容。
